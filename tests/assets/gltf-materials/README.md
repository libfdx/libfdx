# glTF material fixtures

`GltfMaterialsTest` compares imported materials (left) with independently CPU-baked
references (right). Thirteen original cases exercise each material texture slot,
UV1/extension overrides, offset/rotation/negative scale, occlusion strength, normal
scale, supplied/mirrored/generated tangents, nonuniform and mirrored node transforms,
a translated skinned node, and mip-filtered sampling. The normal-grid case checks a
spatially varying normal map with its own UV transform. Both panels use identical
raster coordinates in separate offscreen targets. A perspective inspection bay
surrounds the original probes with solid housings and labels each feature. The
views fit the current framebuffer; hold Left/Right to rotate both views together
and R to reset. The flat probe faces deliberately retain their authored UVs,
tangents, normals, and skinning, so the independently baked reference remains valid.

The original images, geometry and references are generated by
[generate.py](../../core/src/test/fixtures/gltf-materials/generate.py) and use the
repository license. Reference UVs use double-precision CPU transforms packed to
vertices. Constant normal-map references replace the map with independently derived
geometric normals; the skinned reference has its pose baked into geometry.

Additional reference assets include the pinned Khronos `TextureTransformTest`
and a CPU-baked UV derivative, plus `NormalTangentMirrorTest`. These assets are
retained for reference and are not separate chooser scenarios.

Both upstream assets are pinned to revision
`81e8b567643b5166e6ff40024e4ff71ad4b18676`. Each directory's `provenance.json` records
SHA-256 hashes and the source revision; `UPSTREAM.txt` preserves the original notice.
[fetch-khronos.py](../../core/src/test/fixtures/gltf-materials/fetch-khronos.py) reproduces
the downloads. The original upstream data is unchanged; only `khronos/reference.*`
is a derivative with texture transforms baked into UVs.

For pixel comparisons, compare the two equal-width scene regions between the
header and footer, excluding the center divider. Their dimensions follow the
framebuffer rather than a fixed 320×440 target. A tolerance of two channel values
allows rounding differences; also check for nonblank content. Header text differs
between views and is not part of the paired material comparison.
